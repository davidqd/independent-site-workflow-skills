# 选题工作簿规范

本规范定义选题 JSON 和 Excel 队列。`scripts/content_topic_pipeline.py` 支持 `create`、`validate`、`select` 和 `mark`；旧 `article_topic_queue.py` 仅为历史工作流兼容保留。

## JSON 输入

## Excel 字段

脚本按以下顺序建立 `文章选题库`：

1. 选题ID
2. 文章主题
3. 主关键词
4. 次关键词
5. 搜索意图
6. AIDA阶段
7. 目标受众
8. 目标市场
9. 市场定位属性
10. 内容类型
11. 内容集群
12. 核心用户问题
13. 生成渠道
14. 生成依据
15. 证据URL或查询
16. 关键词数据来源
17. 搜索量
18. Ads竞争度
19. SEO难度
20. 趋势
21. 需求得分
22. 业务匹配得分
23. 意图匹配得分
24. 受众匹配得分
25. 内容缺口得分
26. 证据可信得分
27. 优先级总分
28. 建议内部链接
29. 建议CTA
30. 建议字数
31. 处理状态
32. 认领时间
33. 完成日期
34. 内容链接
35. WordPress 内容ID
36. 最终标题
37. 错误说明
38. 产品ID
39. 产品名称
40. 产品关键词
41. 产品库文件
42. 产品库工作表
43. 产品库行号
44. 产品参数依据

`优先级总分` 使用评分公式计算，而不是由模型直接给出。搜索量为真实数值或 `待查询`；Ads competition 与 SEO difficulty 必须分列。

产品库模式必须填写第 38-44 项，并在 `create` 与 `validate` 中添加 `--require-product-aida`。验证器按 `产品ID（没有则产品名称）+ 产品关键词` 分组，要求每组 Attention、Interest、Desire、Action 各一条。`产品参数依据` 只保存原始行非空参数的可读摘要；正式写作仍需按文件、工作表和行号回读原始行。

## 队列状态

- `待处理`：可被每日任务认领。
- `优先`：优先认领。
- `写作中`：已被当前运行认领，避免重复创建。
- `失败待重试`：上次失败，可在后续运行重新认领。
- `草稿已创建`：WordPress 草稿已创建并读回验证。
- `已完成`：本地文章已完成但未创建 WordPress 草稿。
- `已发布`：仅在用户明确发布并完成前端验证后使用。

## 命令行为

- `create`：去重、验证必要字段、创建格式化 Excel；默认要求至少 200 条。
- `validate`：检查条数、字段、AIDA、搜索意图、重复和状态，并输出 JSON 报告；产品库模式额外检查每个产品关键词组合的四阶段完整性。
- `select`：按优先级、顺序或随机策略选择未完成话题；`--claim` 会将其标记为 `写作中`。
- `mark`：串行回写状态、日期、URL、内容 ID、最终标题或错误说明。

不要并行运行多个 `mark` 操作。每次写入后重新打开工作簿验证目标行；需要同时处理多行时也必须逐行串行回写。
