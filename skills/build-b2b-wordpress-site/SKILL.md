## 目标与边界

以“先设计、再搭建、后发布”为默认工作方式，把业务需求转换为可维护、可验证的 WordPress 页面体系。首页是设计母版；首页未通过验收，不批量制作内页。

本 Skill 只保留一个入口。页面设计、主题 Pattern、ACF 产品模板、SEO/GEO、询盘转化和发布验收是同一建站流程的不同阶段，不拆成独立 Skill。

## 全局底线

以下规则适用于所有页面和阶段：

1. 优先复用当前主题的 Patterns、Theme Options、模板和原生组件；内容、数据和布局保持分离。
2. 正式页面由 Gutenberg Blocks、主题 Patterns、主题 Slider 或主题原生组件组成；主要模块必须能在后台独立选中、移动、复制、删除和修改。
3. 不使用单个 Custom HTML、Classic Block、Shortcode 容器或不可拆分代码块承载完整页面或主要区段。
4. 页面内容不得放置 `<style>`，页面级内联 CSS 不得作为正式交付；公共样式放入子主题或统一样式入口，不直接修改父主题。
5. 不编造工厂面积、产能、认证、客户数量、交期、评价、出口国家、客户 Logo 或示例参数。未确认信息使用明确占位符并阻止发布。
6. 参考网站只用于分析布局、节奏和交互，不复制其文字、图片、商标或专有代码。
7. 前台内容默认使用英文；后台说明和执行报告默认使用中文。
8. 保留现有 URL、页面层级和用户内容。所有写入保持小而可验证，默认先写入 Draft、Private 或安全预览副本。
9. WordPress 内容、页面、媒体、Pattern、ACF 值和 SEO 字段优先使用 WordPress MCP；浏览器用于 MCP 缺失接口、必要后台设置和真实视觉验收。
10. 首次使用某主题版本前，先实际验证 MCP 能否返回注册 Pattern 的名称、slug 和原始 Gutenberg 内容。成功时必须用 MCP 采集；失败或内容不完整并记录原因后，才允许浏览器兜底。
11. 同一主题版本已有有效组件目录时复用目录；主题版本、依赖、校验或渲染异常时，只重新采集受影响的 Pattern。
12. 结构回读不能替代视觉验收。参考站重设计必须保存同视口证据，并检查页面框架、首屏高度、视觉焦点和信息密度。

## 默认执行路线

### 1. 只读盘点

确认站点身份、活动主题 slug/版本、父子主题、目标页面、页面状态、菜单、表单、相关设置和可复用组件。只读取本次任务相关资源，不做无差别全量盘点。

### 2. 设计与证据

如有参考站，先检查 1440px 与 390px 的真实页面并建立视觉合同。区分已确认事实、待补资料、可安全使用的通用表达和禁止上线的未验证声明。

### 3. 页面与组件规划

先输出设计 Token、文本线框图和主题组件能力对照表。每个模块必须明确对应 Pattern、Block、Theme Option、Slider、表单组件、ACF 模板或经批准的小型自定义补充。

### 4. 组件与首页草稿

按 Pattern 工作流建立或复用组件目录，把产品分类、应用、质量流程、FAQ 和 RFQ 固化为可复用 Pattern，并记录 ID 与同步策略。先完成首页 Draft 和后台可编辑性检查，再做视觉验收。

### 5. 扩展内页与产品体系

首页通过后，复用设计 Token 和组件构建内页，但不机械复制相同模块。产品较多时先建立一个 Draft 参考产品，再使用 ACF 结构化字段和可复用模板。

### 6. SEO、GEO 与转化

检查 H1/H2/H3、URL、Title、Description、canonical、ALT、内链、Schema、CTA 和表单。Schema 只能描述页面真实显示且已经确认的内容。

### 7. 验收与发布

按照质量门禁验证后台可编辑性、页面结构、真实视口、链接、表单、SEO 抓取状态、演示内容和 Pattern 记录。未验证项写成“未验证”；全部发布门禁通过后才发布或覆盖正式页面。

## 快速安全路径

普通草稿任务默认：

1. 在一次 MCP 会话或批量调用中完成站点预检、主题版本、组件目录、目标页面和代表性 Pattern 回读。
2. 复用与主题 slug、版本、依赖和校验匹配的组件目录；只检查本次会采用或修改的 Theme Options。
3. 通过 MCP 组合已验证 Pattern 与原生 Blocks，先保存 Draft。
4. 一次回读检查状态、H1、表单 ID、Pattern 引用、Classic/HTML/style、演示内容和空链接。
5. 草稿阶段先检查 1440px 与 390px；复杂栅格、断点异常或准备发布时增加 1024px 与 768px。
6. 只有缓存失效、区块报错、样式或交互异常、结构回读不一致时，才升级到对应后台深度检查。

快速路径不得降低全局底线或发布门禁。

## 强制停止发布

出现以下任一情况时停止发布和正式页面覆盖，但继续完成安全的只读检查、规划或草稿：

- 无法确认站点身份、登录状态或目标页面。
- 实现依赖未知主题/插件能力，且 MCP 与浏览器都无法验证。
- 准备发布时无法验证后台区块结构或前台关键视口。
- 主要模块只能通过不可拆分的整页 HTML/CSS 实现。
- 必需的可复用 Pattern 尚未建立，或无法记录名称、ID、同步状态和使用页面。
- 将覆盖用户内容但无法保留修订、备份或安全预览副本。
- 表单、支付、隐私、联系人信息或业务证明来源不明确。
- 参考体验依赖的图片素材不适合所选 Hero 或移动端裁切。

## 最终交付格式

非简单任务使用：

**假设（Assumption）：** 使用的真实信息、占位符和范围假设。
**修改内容（Changed）：** 页面、组件、主题选项、数据、菜单、表单和 SEO 的实际变化。
**验证情况（Verified）：** 实际检查的 URL、状态、断点、表单、链接和后台可视化编辑能力。
**剩余风险（Remaining risk）：** 未验证项目、待补资料、性能或发布风险。

最终报告附“页面模块实现清单”，逐项列出模块、Pattern/Block/Option、Pattern ID、同步状态、使用页面和自定义补充原因。先报告结果，再报告过程；不要把计划写成完成结果。
