# LinkedIn 发布工作流

仅当用户要求发布或定时发布时读取本参考文件。只准备内容时，主 Skill 已经足够。

## 选择发布路径

按以下顺序优先选择：

1. 能够创建并读回帖子的已授权 LinkedIn 连接器；
2. 通过已批准的本地集成使用 LinkedIn 当前官方 Posts API；
3. 浏览器自动化，仅限用户明确选择时。

实现或修改 API 集成前，根据官方文档确认 LinkedIn 当前要求。不得在 Skill 中写死可能过期的 Marketing API 版本。

## 官方 API 不变量

- 从认可的密钥机制获取 OAuth 凭证。
- 发布到个人账号时，验证已认证成员具备所需的成员发帖权限。
- 发布到公司主页时，同时验证所需的组织发帖权限，以及成员在该具体组织中的合格角色。
- 发送 LinkedIn 当前要求的版本和协议请求头。
- 选定帖子类型需要媒体 URN 时，先上传媒体；创建帖子前确认上传已经完成。
- API 要求时，文章链接帖必须显式提供链接元数据，不能依赖 URL 抓取。
- 保存返回的帖子标识符，并且只根据当前官方文档所述行为构造或获取公开 URL。

## 安全发布顺序

1. 解析并展示目标身份。
2. 规范化 canonical 源 URL，并计算内容指纹。
3. 在现有记录和 LinkedIn 读取 API 中搜索匹配的历史帖子。
4. 验证最终文案、链接、可见范围、媒体就绪状态和批准状态。
5. 只发送一次创建请求。
6. 保存 HTTP 或连接器响应、帖子 ID 和时间戳，但不得记录凭证。
7. 权限允许时读回帖子，检查作者、生命周期状态、正文、内容引用和媒体。
8. 记录结果。

如果第 5 步返回超时、网络中断或结果不明确的服务器错误，不得立即重复请求。先搜索近期帖子或已存记录进行对账。

## 浏览器自动化边界

浏览器发布依赖有效的登录会话，可能因登录验证、同意页面、界面变化或账号保护措施而失败。在 `approval-required` 模式下，最终点击前必须展示准确的目标和内容。点击后验证生成的帖子页面或活动记录，并保存其 URL。不得尝试绕过身份验证、验证码、频率限制或平台保护措施。

## 定时运行

启用无人值守运行前：

- 使用相同目标和发布路径，至少手动完成并验证一次运行；
- 确认排程环境可以访问内容源、密钥机制、网络和分发记录；
- 定义时区和停止条件；
- 使用持久化的重复检查键，并串行写入共享队列或记录；
- 保留失败后的重试能力，但创建结果不明确时必须先对账。

无人值守授权必须明确目标身份、允许的内容源或队列、允许的内容类型、运行频率，以及是否允许立即发布。任何范围扩展都需要新的授权。

## 本地执行

用户明确选择本地 LinkedIn API 发布、并且没有可用连接器时，读取[本地 LinkedIn API 发布器](local-api-publisher.md)。先执行无网络写入的预演；确认最终预览后才允许带 `--approve` 发布。Token 只能从认可的密钥机制读取。
