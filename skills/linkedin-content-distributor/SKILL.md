# LinkedIn 内容分发

把已批准的内容源转换为适合 LinkedIn 的内容，并且只在具备适当授权时通过可用的 LinkedIn 发布路径发布。内容准备与外部发布动作必须保持分离。

## 必要输入

优先使用用户已经提供的信息。发布前确认：

- 源文章或内容、适用时的 canonical URL，以及发布状态；
- 目标：已认证的个人账号或明确的公司主页；
- 语言、受众、目标和期望 CTA；
- 模式：`prepare-only`、`approval-required` 或 `auto-publish`；
- 内容形式：纯文本、文章链接、图片、视频、文档或多图；
- 已授权的 LinkedIn 连接，以及目标账号或组织 URN。

只有缺失信息会改变目标、内容或授权边界时，才提出一个简洁问题。不得根据浏览器中的登录状态或无关的历史任务推断发布身份。

## 首次配置

用户首次连接个人账号、询问如何安装配置，或准备把 Skill 分享给其他人时，读取[首次配置指南](references/getting-started.md)。优先引导用户运行 `scripts/linkedin_publish.py setup`，由向导隐藏输入令牌、保存到 macOS 钥匙串并立即验证账号。不得要求用户把令牌粘贴到聊天、普通文件或命令参数中。

## 模式

- `prepare-only`：只创建分发包，在任何外部写入前停止。
- `approval-required`：默认模式。生成预览，等待用户确认准确的目标账号和最终内容后再发布。
- `auto-publish`：仅在用户明确授权指定账号、内容源和排程进行无人值守发布时使用。该授权不涵盖其他账号、内容源、评论、点赞、私信或付费推广。

用户要求定期分发时，必须先手动完整跑通工作流并验证至少一篇帖子。Skill 已存在不代表排程已经启用。

## 工作流

1. 验证内容源。对于文章链接，确认它是预期的、可公开访问的 canonical URL。除非用户明确需要内部预览包，否则不得分发未发布的 WordPress 草稿或私有预览链接。
2. 只提取内容源能够支持的主张。不得编造数据、客户成果、认证、引语、产品规格或归属于作者的观点。
3. 准备符合 LinkedIn 阅读习惯的帖子。以有价值的观察开头，让读者无需打开链接也能理解核心价值，保留重要限制条件，并采用符合目标的 CTA。避免互动诱导、无依据的最高级表述、关键词堆砌和过量 Hashtag。
4. 按照[分发包规范](references/distribution-package.md)创建分发包。除非用户另行要求编辑源文章，否则保持源文章不变。
5. 根据目标账号、近期分发记录、源 URL 和内容指纹检查重复。发现疑似重复时停止并展示已有记录，不得再次发布。
6. 在 `approval-required` 模式下，请求批准前展示准确的帖子文案、媒体、目标身份、可见范围和链接。用户对草稿的批准只授权本次所描述的发布动作。
7. 发布时遵循 [LinkedIn 发布工作流](references/linkedin-publishing.md)。优先使用已授权的官方 API 或连接器。没有可用连接器但用户选择本地 API 时，读取[本地 LinkedIn API 发布器](references/local-api-publisher.md)。只有用户明确选择并理解其稳定性较低时，才使用浏览器自动化。
8. 读回或通过其他方式验证结果。记录帖子 ID、可用时的公开 URL、目标、时间戳、源 URL、内容指纹和验证状态。不能仅凭一次点击就报告成功。

## 内容改写

- LinkedIn 链接帖是指向源文章的社交帖子，不应被当作 LinkedIn 原生长文章或 Newsletter。
- 除非用户指定目标语言，否则保持源内容语言。翻译时保留事实含义和专有名称。
- 只有确实有助于发现内容时才使用少量相关 Hashtag，不强制固定数量。
- 公司主页帖子只有在品牌指南或源材料提供依据时，才采用组织口吻。
- 个人账号帖子不得编造第一人称经历、个人观点或成果。当作者观点会实质影响真实性时，应先询问。
- 只有已确认所有权或使用权时才使用源媒体，并为上传图片提供有意义的 Alt 文本。

## 发布边界

- 不得在 Skill、源文件、日志或分发记录中请求、打印或保存 Access Token。使用运行环境认可的密钥或连接器机制。
- 目标账号或组织的身份与授权验证完成前不得发布。
- 不得在官方 API 或连接器失败后悄悄改用浏览器自动化。
- 除非用户另行请求并授权，否则不得创建广告、赞助帖、私信、评论、点赞、邀请或账号变更。
- 不得把 API 接受请求视为最终验证；应保存返回的标识符，并在现有权限允许时核验已发布对象。
- 发生认证、权限、频率限制、媒体上传、重复检查或验证失败时，停止处理该条内容，保留可重试记录，不得宣称成功。
- 不得自动重试结果不明确的发布请求；必须先确认 LinkedIn 是否已经创建帖子，避免重复发布。

## 从写作 Skill 交接

在 `$geo-article-writer` 之后调用时，接收其已经验证的已发布文章包：最终标题、canonical URL、摘要、受众、语言、特色图详情、可复用事实主张和 CTA。写作 Skill 继续负责文章本身；本 Skill 负责 LinkedIn 改写、授权、发布和分发记录。

## 完成标准

准备阶段完成意味着分发包包含最终文案、内容源、目标、媒体方案、模式和未解决事项。发布阶段还必须具备经过验证的目标、LinkedIn 返回的帖子标识符、已记录的结果，以及 LinkedIn 提供时可用的帖子 URL。明确区分 `已准备`、`等待批准`、`已发布并验证`、`已发布但未验证` 和 `失败`。
